## RPC — RPC 核心框架

> 代码位置：`NewLife.Remoting/` — ApiMessage, IEncoder, EncoderBase, OwnerPacket, ApiAction, ApiManager, IApiHandler, ApiClient, ApiServer, ICluster, IRetryPolicy 等

>
> 元数据传递（RPC-11）和重试策略（RPC-12~RPC-15）是 ApiClient 的内置小功能，作为 RPC 子项纳入。

## 发版待办：相对 3.9 的行为变化（正式发版时需写入 ChangeLog）

> v12 适配已完成但尚未正式发版：`ChangeLog.md`、`VersionPrefix`、`PackageReleaseNotes` 保持 3.9 原状，正式发版时统一更新，并把下述行为变化写入 ChangeLog。

**破坏性变更**

| 变更 | 影响与替代方案 |
|------|----------------|
| `WsClient` 类删除 | ws:// 承载 SRMP 的能力取消。SRMP 请用 `ApiClient` 的 `tcp://`/`udp://`；HTTP 调用请用 `ApiHttpClient`（`http://`/`https://`） |
| `Http.HttpCodec`、`WebSocketClientCodec`、`WebSocketServerCodec` 删除 | 自研 HTTP/WS 帧栈整体退场，HTTP 入口改用 NewLife.Core 的 `HttpServer`；自定义帧协议请直接实现 `IMessageCodec` |
| `HttpMessage` 帧层方法删除（`TryParse`/`WriteHeader`/`Read`/`ToPacket` 等） | 该类只承载动作分发所需的头部与负载；HTTP 报文的解析与写出由 Core 负责 |
| 同端口三协议取消 | `ApiServer` 主端口只跑 SRMP；HTTP 需显式设置 `HttpPort`（默认关闭）。原「一个端口既跑 RPC 又跑 HTTP/WS」的部署需改为双端口 |
| `IApiHost.GetMessageCodec()` 返回类型 | 由 `IPipelineHandler` 改为 `IMessageCodec`（重载该方法的子类需同步调整，返回 `SrmpCodec` 即保持原协议） |
| `RemotingServiceResolver` 不再解析 ws/wss 地址 | 配置里的 `ws://`、`wss://` 地址会抛 `NotSupportedException`，请改为 `tcp://`/`udp://` 或 `http(s)://` |
| 目标框架由 10 个收敛为 7 个（`net45;net461;netstandard2.0;netstandard2.1;net6.0;net8.0;net10.0`） | 对齐 NewLife.Core v12：net5.0/net7.0/net9.0 已由上游合并（net5.0→netstandard2.1，net7.0→net6.0，net9.0→net8.0）。消费方框架不变、NuGet 资产自动回退，但包内不再提供这三个 TFM 的专用程序集 |
| 运行时消息改为英文原文 | 异常与日志文案的**英文原文**是词表键；中文环境仍显示中文（`Locales/zh-Hans.yml`），其他语言回退英文。按中文文案做字符串匹配的调用方需改用 `ApiCode` 或错误码判断 |

**行为变化（兼容）**

- HTTP 入口基于 Core `HttpServer`：keep-alive、分块传输、`Expect: 100-continue`、HEAD 等 HTTP/1.1 语义由 Core 处理；路由为兜底 `/{*path}`，动作名仍按 URI 解析（`/Api/Info` → `Api/Info`），参数与令牌传递方式不变。
- WS 握手请求收到 `501 Not Implemented`（明确不支持），而不是被静默升级后空等。
- 大帧（超过 Socket 缓冲区）与并发请求在 v12 下的行为与 3.9 一致：由 SDK 内部完成流式体物化与序列号配对。
