## RPC — RPC 核心框架

> 代码位置：`NewLife.Remoting/` — ApiMessage, IEncoder, EncoderBase, OwnerPacket, ApiAction, ApiManager, IApiHandler, ApiClient, ApiServer, ICluster, IRetryPolicy 等
> 排序原则：协议消息 → 编解码 → 内存管理 → 元数据模型 → 处理流水线 → 连接管理 → 客户端/服务端 → 会话扩展 → 元数据传递 → 重试策略
>
> 元数据传递（RPC-11）和重试策略（RPC-12~RPC-15）是 ApiClient 的内置小功能，作为 RPC 子项纳入。

| 变更 | 影响与替代方案 |
|------|----------------|
| `WsClient` 类删除 | ws:// 承载 SRMP 的能力取消。SRMP 请用 `ApiClient` 的 `tcp://`/`udp://`；HTTP 调用请用 `ApiHttpClient`（`http://`/`https://`） |

- HTTP 入口基于 Core `HttpServer`：keep-alive、分块传输、`Expect: 100-continue`、HEAD 等 HTTP/1.1 语义由 Core 处理；路由为兜底 `/{*path}`，动作名仍按 URI 解析（`/Api/Info` → `Api/Info`），参数与令牌传递方式不变。

- 大帧（超过 Socket 缓冲区）与并发请求在 v12 下的行为与 3.9 一致：由 SDK 内部完成流式体物化与序列号配对。

### AOT 改造的关键发现（供其他 NewLife 库参考）

1. **匿名类型在 NativeAOT 下会被裁剪**：`JsonHelper.Write(runtimeValue)` 对匿名类型返回 `{}`。库内部凡是构造协议报文的匿名类型都是隐患（本次修复 HTTP 响应封套与客户端注销/升级参数两处）。
2. **`DynamicDependency` 对"运行时枚举成员"的路径无效**：实测打 `[DynamicDependency(PublicProperties, typeof(T))]` 后 `JsonHelper` 仍序列化为 `{}`；可靠机制是 `[JsonSerializable]` 标记（Core 生成器落访问器表）或 `typeof(T)` 传给带保留注解的 `Type` 参数。
3. **动作入参/返回类型需要在编译期显式保留**：否则 FastJson 反序列化报 `No parameterless constructor defined for type 'X'`——这是"反射能跑但元数据已丢"的典型表现，JIT 下完全不可见。
