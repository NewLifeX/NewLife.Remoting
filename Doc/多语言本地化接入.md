# 多语言本地化（L.T）

本文档说明 NewLife.Remoting 两个包如何接入 NewLife.Core v12 的运行时本地化能力：英文原文为词表键、`Locales/*.yml` 提供译文、`L.T(...)` 在抛异常处显式翻译，日志由 `Logger.Format` 自动翻译。

## 1. 设计取舍

| 项 | 选择 | 理由 |
|---|------|------|
| 词表键 | **英文原文** | 未提供译文的语言自动回退英文，接入成本为零；键即文案，不存在"键名与文案两层维护" |
| 译文载体 | `Locales/*.yml`（编译期源生成） | 不依赖 `ResourceManager` 与卫星程序集，NativeAOT 下可用，词表以 Deflate 压缩内嵌 |
| 译文语言 | 内置 31 种语言，与 NewLife.Core 词表集合保持一致 | 简体 `zh-Hans`、繁体 `zh-Hant`（统一承接 `zh-TW` / `zh-HK` / `zh-MO`）为主维护语言，其余 29 种语言随版本同步；未列出的区域性回退英文 |
| 翻译入口 | 异常 `L.T(...)`；日志直接写英文模板 | `Logger.Format` 已统一翻译日志，`XException` 构造器已统一翻译自定义异常 |
| 不翻译的内容 | `[Description]`/`[DisplayName]`/`[Justification]`/XML 注释、设备历史记录文本、协议报文与结构化日志 | 元数据与持久化数据应保持稳定，随写入时的语言漂移会让历史记录前后不一致；`[{0}]=>{1}`、`commandId=...`、统计表格等结构化日志不承载自然语言 |

## 2. 目录与文件

```
NewLife.Remoting\Locales\{ar,bn,cs,da,de,el,es,fa,fi,fr,he,hi,hu,id,it,ja,ko,ms,nb,nl,pl,pt,ro,ru,sv,th,tr,uk,vi,zh-Hans,zh-Hant}.yml
NewLife.Remoting.Extensions\Locales\{同上 31 种}.yml
```

- 每个组件维护自己的 31 份词表，模块初始化时自动 `Localization.Register`；类库默认**不覆盖** Core 同名译文。
- 语言集合与 NewLife.Core 的 `Locales/` 完全对齐，下游项目引用本库后无需再补语言文件。
- 引用 `NewLife.Core` 包时，包内 `build/NewLife.Core.props` 会把 `Locales/*.yml` 自动挂成 `AdditionalFiles`，**无需改 csproj**。
- 词表格式为逐行 `"英文原文": "译文"`，键必须与源码字符串**逐字一致**（含空格与标点）。

## 3. 编码约定

```csharp
// 自定义异常：XException 构造器自动翻译，直接写英文
throw new XException("Session {0} is closed.", sessionId);

// BCL 异常与 ApiException：显式翻译
throw new ApiException(ApiCode.NotFound, L.T("Cannot find service named [{0}]!", action));
throw new InvalidOperationException(L.T("Streaming return type {0} does not implement IAsyncEnumerable<T>", type));

// 日志：写英文模板与参数，Logger.Format 自动翻译（不要用字符串插值）
Log?.Error("Login failed: {0}", ex.Message);
WriteLog("Update found: {0}", info.ToJson(true));

// 带实例前缀：使用 Core 的 *Prefixed 扩展，前缀不参与翻译
Log?.ErrorPrefixed("[" + Name + "]", "Login failed: {0}", ex.Message);
Log?.WritePrefixed(LogLevel.Debug, "[" + Name + "]", "WebSocket connection closed [{0}]", errorCode);

// 埋点标签：AppendTag 只接受单参数，需显式翻译
span?.AppendTag(L.T("Session [{0}] not found, cannot process the message.", code));
```

**禁止字符串插值**（`$"..."`）：模板在进入日志/翻译前已被展开，无法再查表。需要格式化时一律写成"模板 + 参数"。

**名称前缀不进入词表键**：带实例前缀的日志统一使用 NewLife.Core 的 `InfoPrefixed` / `ErrorPrefixed` / `WritePrefixed` 扩展，内部先按 `LogCulture` 翻译并格式化消息，再拼接前缀。`ApiHost`、`ClientBase`、`Upgrade`、`ClientSingleCluster`、`ClientPoolCluster` 的 `WriteLog` 包装器均走这条路径。新增同类日志时不要写成 `$"[{Name}]{format}"`，也不要把 `[{0}]` 前缀放进格式串的占位符，否则前缀会进入词表键，导致查表失败或译文携带实例信息。

**自定义宿主接入请求语言**：在请求入口创建作用域即可复用同一套解析逻辑（q 权重、非法语言忽略、释放还原）：

```csharp
using var culture = RequestCultureScope.Create(context.Request.Headers.AcceptLanguage.ToString());
```

> 当前示例使用 Remoting 本地 `NewLife.Remoting.RequestCultureScope`；NewLife.Core 下一版提供 `NewLife.RequestCultureScope`，届时可直接替换。

## 4. 校验与门禁

```powershell
# 语言清单（locales.json，与 NewLife.Core 对齐）+ 词表键集合、占位符、格式说明符、
# 孤儿键（按完整字符串字面量匹配）+ L.T 引用键必须存在于同组件基准词表
pwsh -File check-locales.ps1

# 运行时消息不得含中文（注释与特性参数不受限）
pwsh -File check-english-exceptions.ps1

# 盘点模式（不失败），用于新增文案后普查
pwsh -File check-english-exceptions.ps1 -List
```

两条命令都在 `.github/workflows/test.yml` 的 `build` 作业中执行，任一失败即阻断合并。

## 5. 测试约定

- 测试进程在 `TestSetup` 中固定 `Localization.Culture = en-US`，断言直接针对英文原文，避免机器区域设置影响结果。
- `LocalizationTests` 抽样验证简体、繁体、德语与英文回退四种路径，并放入 `GlobalState` 串行集合，避免与并行用例互相污染。
- 新增译文时同步补一条断言，确保词表真的被源生成器打包进程序集。

## 6. 新增词条的流程

1. 源码中把中文消息改为英文模板；异常用 `L.T`，日志用模板 + 参数。
2. 在对应组件 `Locales/` 下的 31 个语言文件各加一行，键为英文原文；确定来不及翻译的语言可暂缺，运行时按英文回退。
3. 运行 `pwsh -File check-locales.ps1` 与 `check-english-exceptions.ps1` 确认通过。
4. 编译后词表在模块初始化时注册；缺译文的语言按英文回退，不会抛异常。

## 7. 已知边界

- **设备历史记录**（`WriteHistory` 的标签与明细）按数据对待，仍为中文；如需多语言展示，应由读侧按标签码翻译，而不是写入时按当前语言落库。
- **协议报文与结构化日志**（`[{0}]=>{1}`、`commandId=...`、统计表格等）不含自然语言，保持英文/符号形式，不进入词表。
- **服务端响应语言**：`RequestCultureScope` 会按 `Accept-Language` 的 q 权重切换当前 UI 文化，请求结束自动还原，已接入 `ApiHttpHandler`、最小 API 端点与 MVC `[ApiFilter]`。NewLife.Core 下一版将提供 `NewLife.RequestCultureScope`，按“最高权重且存在译文表”的语言选择（最高权重语言不支持时退守下一个受支持语言，全部不支持时保持宿主语言）；Remoting 本地类型暂时保留（当前仍按最高 q 的合法区域性选择），待下次升级 `NewLife.Core` 后迁移并删除。宿主已配置 ASP.NET Core `RequestLocalization` 时，`[ApiFilter]` 与最小 API 端点检测到 `IRequestCultureFeature` 后直接采用宿主选择；未配置时继续使用内置解析。宿主仍可全局固定 `Localization.Culture`（此时请求头不生效）；不要在并发服务中临时修改全局 `Localization.Culture`。HTTP 客户端发送 `Accept-Language` 即可指定响应语言；SRMP/TCP 没有标准语言协商，客户端应以 `ApiException.Code` 为准自行本地化，或由业务在登录/请求中携带语言。**.NET Framework 目标不做请求级切换**（`CurrentUICulture` 为线程静态，异步请求间可能串语言），保持宿主语言。
- **日志语言**：默认跟随 `Localization.Culture` 或当前 UI 文化；开启请求语言协商后，建议设置 `Localization.LogCulture` 固定宿主语言，避免同一进程的日志随请求语言漂移。`*Prefixed` 扩展与 `Logger.Format` 都优先读取 `LogCulture`。
- **`InvariantGlobalization=true`** 下具名区域性不可用，源生成器会跳过注册，运行时全部回退英文。
- 词表随程序集编译，新增语言需要重新发版；运行时临时补充语言可用 `Localization.Register(culture, table)`。
